Vibepaws · 功能审计 + 方案设计

习惯驱动的宠物 —— 行为、气泡、进化都从你的工作习惯学习

依据 src/core、src/db、src/adapters、 docs/mvp_architecture.md 与 README.md 审计。结论： 它已经记录了丰富的「单 session」行为，但还没有把信号聚合成「用户级」的工作习惯画像 —— 所以目前宠物的进化、动作和气泡语气对习惯都是「盲」的。 本文规划那一层，让宠物真正「像你养的」。

✅ 已具备

单 session 行为采集

隐私优先的事件管道（5 个 adapter → Core → SQLite）已在记录 token、context、 correction、goal、等待时长、工具与结果。

⚠️ 部分具备

有信号、无画像

原始工作习惯信号都在，但没有把跨 session 的信号聚合成「用户」画像 （节奏、工具风格、专注度、精确度）。

❌ 缺失

习惯 → 宠物（进化 + 行为 + 语气）

进化只读 level + health_score；宠物的动作、情绪、气泡措辞全是写死的 —— 与习惯零关联。

02工作习惯模型

八个维度，全部可以从已采集的数据推导出来。「工作习惯」不只是你何时写代码 —— 更是你怎么写代码。

🕐 作息类型（Chronotype）

你何时工作：早鸟 / 白天 / 夜猫。来自 received_at 的活跃时段直方图。

📈 节奏（Cadence）

爆发（很多短 session）vs 平稳（少数长 session）vs 稀疏。来自 session 频率 + 时长。

🎯 专注深度（Depth）

深度工作 vs 浅层。长时间不中断 + 干净的 context = 深度；频繁切换 = 浅层。

🧰 工具风格（Tool style）

CLI 重 / 编辑重 / 测试先行 / 提交驱动。来自 tool_name 分布。

🎯 精确度（Precision）

correction 循环少 = 精确；反复改 = 探索型。来自 correction_count。

🧭 上下文卫生（Context hygiene）

你多常把 context 推到 85% 以上。来自 context_pct 越界次数。

⚡ 响应速度（Responsiveness）

你多快回应 agent。来自 needs_input_since 的时长。

🏁 结果偏好（Outcome bias）

交付型（提交/成功）vs 探索型（partial/abandoned）。来自 outcome 分布。

设计原则：保持 Core 确定性 —— 它只存数字和少量分类标签（例如 chronotype=night_owl、cadence=burst）。所有 呈现层（用哪套动画、哪个 emoji、 哪种措辞）都放在 渲染层。这跟现有哲学一致：Core 做判定、UI 做渲染；通知已经带 i18n key 让渲染层选语言 —— 我们在这套机制上再加一条 voice（语气）轴。

03习惯 → 宠物行为

宠物的动画套件、精力值、反应方式变成习惯画像的函数。「行为」= 待机变体 + 情绪 + 作息周期 + 反应阈值。

习惯信号→宠物行为
chronotype = night_owl→夜里醒着、白天打盹；月光色调的待机；你熬夜 session 时精神抖擞。
chronotype = early_bird→清晨明亮活泼；天黑后就犯困。
cadence = burst→高精力待机（快速蹦跳），对每个事件都反应很快。
cadence = steady→平稳呼吸、缓慢摇尾、很少躁动。
cadence = sparse→经常打盹；你回来时伸个大懒腰。
depth 高→working 时进入「心流」专注姿态 + 柔光。
depth 低→工作时来回踱步、东张西望、坐立不安。
precision 低（correction 循环）→歪头「等待」姿态，凑近编辑处。
responsiveness 高→积极 —— needs-you 时摇尾巴 + 快速抬头。
responsiveness 低→回合之间打瞌睡，然后惊醒。
outcome_bias = shipper→finished 时得意 / 庆祝。
outcome_bias = explorer→好奇，凑近看你探索了什么。

BehaviorDirector（渲染层，ui/）

// ui/behavior.js —— 把 HabitProfile 映射成动画参数。纯函数、可单测。
export function behaviorFor(habit) {
  const energy = {
    burst: 1.0, steady: 0.45, sparse: 0.2,
  }[habit.cadence] ?? 0.5;

  return {
    idleVariant: habit.depth > 0.6 ? "focused"
               : habit.cadence === "burst" ? "bouncy"
               : habit.cadence === "sparse" ? "sleepy"
               : "calm",
    wakeWindow: habit.chronotype === "night_owl" ? [20, 4]   // 晚 8 点 – 凌晨 4 点
              : habit.chronotype === "early_bird" ? [5, 21]
              : [8, 23],
    reactionMs: 900 - energy * 500,        // burst 反应更快
    fidget: 1 - habit.precision,           // 精确度低 → 更躁动
    celebrate: habit.outcome_bias === "shipper",
  };
}

04习惯 → 气泡语气

气泡的内容不变（还是那个通知事件），但语气 —— 口吻、emoji、节奏、措辞 —— 会随你的工作方式变化。叠加在现有 i18n key/params 体系之上。

习惯信号→气泡风格
night_owl→🌙 「凌晨 1 点还在发版」「夜色正好」。
burst→短促有力 ⚡ —— 「又来了？上」「3 个搞定，下一个」。
deep work→极简安静 —— 「context 40%」（不闲聊），不用 emoji 打扰。
correction loop→温和提醒 —— 「同一文件改第 3 次了，开个新 session？」。
test-first→✅ 庆祝 —— 「测试绿了，已交付」。
cli-heavy→终端梗 —— 「$ cd done」「exit 0」。
shipper→提交/收工时自豪口吻 —— 「又一个交付了 🚀」。
explorer→好奇口吻 —— 「这波绕得挺有意思」。
distracted（回应慢）→温柔再提醒 —— 「你有空我就在 👋」。

语气系统（渲染层，ui/）

// ui/voice.js —— 同一个 i18n key，按习惯选不同的语气变体。
export function renderBubble(notif, habit) {
  const variant = voiceVariant(notif.type, habit);   // "punchy" | "quiet" | "gentle" | "proud"
  // i18n key 仍是语言的权威来源；variant 只决定 emoji / 节奏 / 措辞。
  return t(notif.i18n.body.key, { ...notif.i18n.body.params, ...variant.emoji });
}

function voiceVariant(type, h) {
  if (type === "milestone" && h.tool_affinity.includes("test"))
    return { emoji: "✅", pacing: "proud" };
  if (type === "drift")
    return { emoji: "🤔", pacing: "gentle" };
  if (h.depth > 0.6)
    return { emoji: "", pacing: "quiet" };
  if (h.cadence === "burst")
    return { emoji: "⚡", pacing: "punchy" };
  return { emoji: "", pacing: "normal" };
}

05实施方案 —— 5 个阶段

增量式、不破坏现有功能。阶段 1–2 在 Core 里搭「习惯大脑」；阶段 3–4 把它接到进化、行为、语气；阶段 5 暴露给用户。

阶段 1 —— 习惯数据模型

schema.ts · migrate.ts

两张表：一张按天汇总（时间序列）+ 一张单行 习惯画像（指数衰减后的摘要）。只存数字，绝不存原始内容。

  • behavior_daily(day, agent, active_min, sessions, tokens, commits, tests, corrections, errors, context_85, …)
  • habit_profile(id, chronotype, cadence, depth, precision, context_hygiene, responsiveness, outcome_bias, tool_affinity, updated_at)
  • 复用现有 memories 表作为「洞察」流水。

阶段 2 —— HabitEngine（Core）

新增 src/core/habit.ts · 接入 server 事件链

纯「事件的函数」引擎，接进与 registry / exp 相同的分发链。把每条事件折进按天汇总， 并用指数衰减重算 8 维画像。

  • 首次运行时用已有 events + sessions 回填。
  • 向 memories 写洞察行（例如 chronotype=night_owl）。
  • 暴露 GET /api/habit，并把 habit 塞进 pet_state 的 SSE 推送。

阶段 3 —— 习惯 → 进化

exp.ts checkEvolution · seed.ts evolution_meta

给 evolution_meta.conditions 增加习惯键 —— 进化本来就是配置驱动，所以这是语义扩展，不是重写。

  • conditions: ["health>=0.7", "chronotype=night_owl"] → 夜猫形态。
  • conditions: ["depth>=0.6"] → 「专注」变体；cadence=burst → 「火花」形态。
  • 没有习惯条件命中时，回落到今天的 level+health 规则。

阶段 4 —— 习惯 → 行为 & 气泡语气

ui/behavior.js · ui/voice.js · ui/app.js

渲染层从 SSE 拿 habit。Core 保持确定性，所有呈现都映射在这里。

  • behaviorFor(habit) → 待机变体、精力、作息窗口、反应阈值、躁动程度。
  • renderBubble(notif, habit) → 按通知类型 + 习惯选口吻/emoji/节奏。
  • 作息周期镜像 chronotype；在你活跃窗口之外宠物会「打盹」。

阶段 5 —— 设置 + 隐私

settings.html · server.ts · reset.ts
  • 「你的宠物懂你」面板：作息、节奏、工具风格、专注度 —— 只读，带「忘掉我的习惯」。
  • /api/reset 增加 habit 作用域；提供关闭开关（「宠物保持中性」）。
  • 画像只有数字 —— 永不存 prompt、代码、路径，也绝不外发。永远。

Schema（追加到 SCHEMA_SQL，提升 SCHEMA_VERSION）

-- 按天汇总：每天、每个 agent 一行，从 events/sessions 折出
CREATE TABLE IF NOT EXISTS behavior_daily (
  id INTEGER PRIMARY KEY,
  day TEXT NOT NULL,               -- 'YYYY-MM-DD'（UTC）
  agent TEXT NOT NULL,
  sessions INTEGER NOT NULL DEFAULT 0,
  active_min REAL NOT NULL DEFAULT 0,
  tokens INTEGER NOT NULL DEFAULT 0,
  commits INTEGER NOT NULL DEFAULT 0,
  tests INTEGER NOT NULL DEFAULT 0,
  corrections INTEGER NOT NULL DEFAULT 0,
  errors INTEGER NOT NULL DEFAULT 0,
  context_85 INTEGER NOT NULL DEFAULT 0,
  UNIQUE (day, agent)
);

-- 单行用户工作习惯画像（聚合、指数衰减）
CREATE TABLE IF NOT EXISTS habit_profile (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  chronotype TEXT,               -- 'early_bird' | 'day' | 'night_owl'
  cadence TEXT,                  -- 'burst' | 'steady' | 'sparse'
  depth REAL NOT NULL DEFAULT 0.5,          -- 0..1 深度工作
  precision REAL NOT NULL DEFAULT 0.5,      -- 0..1（1 = 很少反复改）
  context_hygiene REAL NOT NULL DEFAULT 0.5,-- 0..1（1 = 干净）
  responsiveness REAL NOT NULL DEFAULT 0.5, -- 0..1（1 = 回应快）
  outcome_bias TEXT,             -- 'shipper' | 'explorer'
  tool_affinity TEXT NOT NULL DEFAULT '[]', -- JSON：[tool_name, …] 加权
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

HabitEngine 骨架（src/core/habit.ts）

import type Database from "better-sqlite3";
import type { CoreEvent } from "./events.ts";

export class HabitEngine {
  private db: Database.Database;
  constructor(db: Database.Database) { this.db = db; }

  // 接进与 registry/exp 相同的分发链（server.ts）
  handle(ev: CoreEvent): void {
    const day = ev.timestamp.slice(0, 10);
    switch (ev.event_type) {
      case "agent_working":
        if (ev.payload.tool_name === "Bash") this.bump(day, ev.agent, "tokens");
        break;
      case "context_update":
        if ((ev.payload.context_pct ?? 0) > 85) this.bump(day, ev.agent, "context_85");
        break;
      case "session_finished":
        this.bump(day, ev.agent, "sessions");
        this.recompute();  // 把今天的汇总折进 8 维画像
        break;
    }
  }

  private recompute(): void { /* 聚合 behavior_daily → habit_profile，带衰减 */ }

  get(): Record<string, unknown> {
    return this.db.prepare("SELECT * FROM habit_profile WHERE id=1").get() ?? {};
  }
}

08隐私护栏（必须保留）

习惯层必须继承仓库现有的双闸隐私姿态，而不是削弱它。

保持不变

  • 只有白名单 payload 字段进入 Core（第二道闸在 ingress.ts）。
  • 习惯模型只存 派生数字 + 分类标签，绝不存 prompt/代码/路径。
  • 所有数据都在本地 .vibepaws/vibepaws.db。

需要新增

  • /api/reset 增加 habit 作用域（一键「忘掉我的习惯」）。
  • 提供退出开关：「宠物保持中性」可关闭行为/语气自适应。
  • behavior_daily 只保留计数 —— 不外发、不上云。
